# 里々のチェック結果の読み方

`scripts/check.ps1`（`check-dic.ps1`、`lint.ps1`）と `scripts/shiori.ps1` の出力の扱い。全体の手順は `references/workflows/check.md`。

## 里々の 3 つの調べ方

里々は、辞書を読み込むときに文法をほとんど検査せず、文を実行するときに解釈する。そこで、調べ方が 3 つある。

| 調べ方 | 見つかるもの | 実行 |
|---|---|---|
| `check-dic.ps1` | 読み込みで分かるもの（閉じていない `（`、`＠SAORI` の誤り、読めない辞書） | 辞書を読み込むだけ |
| `lint.ps1`（ShioriLint。Mc206-1 以降） | 辞書の字面から分かるもの（`＄` の行の書式、式の誤り、内蔵関数の引数の個数、どこにも無い `（名前）`、飛び先の書き間違いなど）を、**実行せずに**全部 | しない |
| `check-dic.ps1 -Run`、`shiori.ps1` | 実際に実行しないと分からないもの（実行時に決まる名前、SAORI の戻り値、循環呼び出し） | する |

まず `check.ps1` で上の 2 つを行い、直したトークや関数は `shiori.ps1` で実際に呼ぶ。`lint.ps1` は、条件付きの文や名前のない文（ランダムトーク）も含めて、辞書の全体を 1 秒ほどで調べられる（`-Run` は名前が単純な文しか実行しない）。

## lint の読み方（`scripts/lint.ps1`）

tamacs.exe で `satori.dll` に、`ghost/master` の一時コピーを読み込ませ、`ID: ShioriLint`（`SecurityLevel: local`）を送る。結果は `ghost/master/dic01.txt(12) : error: 内容` の形（ゴーストのルートからのパス、元ファイルの行）。仕様の全体は https://ukatech.shillest.net/satori-docs/shiori/lint/ 。

- **error**: 書き方として誤りで、実行しても意図どおりにならないと確実に言えるもの。直す。終了コードは 1 になる。
  - `＄による変数代入文には、タブによる区切りか、＝による計算式が必要です` / `数字のみの変数名は扱えません` / `計算式が正しくありません` / `「set」の引数の個数が正しくありません` / `（ が閉じられないままファイルが終わっています。この行以降が読み込まれません`（その後ろの辞書が読まれていないので、ほかの指摘も減る。先にこれを直して、もう一度行う）。
  - `lint: critical: SATORI : …` の行は、里々が辞書を読み込むときに出したエラー（`check-dic` と同じもの）。
  - `（` を含む式は、実行時の値が分からないので、`1` に置き換えて調べる。計算できないとき、`（）` を含む式なら warning にとどまる。
- **warning**: 誤りの可能性が高いが、断定できないもの。1 件ずつ確かめる。`-Strict` なら失敗になる。
  - `「名前」は、単語群・文・変数・内蔵関数・SAORIのどれにも見つかりません`: 名前の書き間違いか、`（笑）` のように文字として表示したい括弧。表示のつもりなら `φ（笑）` と書く（警告も実行時の `not found` のログも出なくなる）。
  - `ジャンプ先「フラグ処理 」という＊の文はありませんが、…違う「フラグ処理」があります`: 飛び先の書き間違い（末尾の空白、全角半角、大文字小文字）。
  - `同じ名前「名前」の単語群と文があります`、`＠の本文では、＄の行は変数の代入になりません` など。
- **notice**: 書き方としてありうるもの。既定では数だけ出る（`-Notice` で表示）。意図と合っているか見たいときだけ見る。
  - `ジャンプ先「名前」という＊の文が見つかりません`: ひな形が用意する任意のフック（`＞他のゴーストから変更` など）として使われることが多いので、error にしない。名前の打ち間違いでないかだけ確かめる。
  - 辞書に `＄（名前）＝…`、`split_to`、`単語の追加` のような、実行時に名前が決まる変数や単語群を作る記述があると、見つからない名前は warning でなく notice になる（あるのかもしれないため）。
- `ほかN件は省略しました`（info）: 問題が多すぎて表示を省いた。error は優先して残るので、直してもう一度行う。
- `replace.txt` の置き換えは適用してから調べる。`＄` の行に `【タブ】` が置き換えられずに残っていると、`replace.txt` に定義が無い。
- `＄辞書フォルダ` で読むフォルダを絞っているゴーストは、読み込んでいない辞書を調べない。
- `lint: SKIPPED - satori.dll … has no ShioriLint` のときは、satori.dll が Mc206-1 より古い。更新するかは作者に確かめる（`references/satori/update.md`）。
- 行は元ファイルの行番号。`（` が複数行にまたがるときは、その `（` を含む論理行の先頭の行になる。

## check-dic の error

tamacs.exe で `satori.dll` に `ghost/master` の一時コピーの辞書を読み込ませ、里々のログからエラーを拾う（パターンは `scripts/shiori/satori/satori.json`）。

- `カッコの対応関係が正しくない部分があります。` / `辞書は正しく読み込まれていません。`（その前の行に、対象の辞書ファイルのパスが出る）: 閉じていない `（` がある。カッコを文字として使うときは `φ（` と書く。全角の `（` `）` の数と、`）` の閉じ忘れを、表示されたファイルから探す。
- `SAORI読み込み中にエラーが発生: <行>`: `satori_conf.txt` の `＠SAORI` の行の誤り（`呼び出し名,相対パス` の形か、重複した呼び出し名か、DLL が無いか）。`saori/` のファイルの有無も見る。`SakuraDLLClient::load '…' ...failed.` は、SAORI の DLL が読み込めなかった（中身が SAORI でない、依存するライブラリが無いなど）。
- `loading dic…txt... failed.` / `no dictionary file (dic*.txt) was loaded`: 辞書が読めない、または 1 つも無い。辞書は `ghost/master` の直下の `dic*.txt` だけが読まれる（`＄辞書フォルダ` で変えていなければ、`another/` などの下のファイルは読まれない）。
- `loading satori_conf...failed`（warning）: `satori_conf.txt` が無いので、`＊初期化` と `＠SAORI` が読まれない。

## `-Run` のとき（展開中のエラー）

名前が単純な文（`＊名前`。条件付きと、名前のない文を除く）を一時コピーの中で 1 回ずつ実行し、その間のエラーも拾う。

- `（名前、引数） not found.`（引数付きなので関数呼び出しとみなす。関数名の打ち間違いか、`＠SAORI` に登録していない SAORI）
- `式が計算不能です。`（式のカッコの数、演算子、0 での除算を確かめる。`＄名前＝(?&部品)…` のように、正規表現のパターンを `＝` で代入しても出る。タブ区切りで代入する）
- `[error] (internal ssu) - regex_match : 400 Bad Request / 呼び出しの不備`（`regex_` 関数のパターンやオプションの誤り。閉じていない括弧、`(?&名前)` の名前が無い、オプションに `i` `s` `m` `x` 以外の文字、など）。`正規表現の書式が正しくありません（…）。` といった説明の文は、ログではなく**台詞（関数の戻り値）に入る**。その中の `（…）` が名前として展開されて、`（undefined subroutine '名前'） not found.` のような警告が続けて出ることがある（原因は直前の `regex_` 呼び出しだと、hint が示す）。`regex_` 関数の誤りは、`check-dic`（`-Run` なし）と `lint.ps1` では見つからない。直した文は `shiori.ps1 -Eval` や `-Run` で実行して確かめる（`references/satori/dictionary.md` の「正規表現」）。
- `引数が足りません。` などの引数の誤り
- `※　＄による変数代入文には…　※`（`＄` の行に、タブか `＝` が無い）
- `呼び出し回数超過`（循環呼び出し）、`ジャンプ回数超過`、`括弧展開サイズ超過`
- `（名前） not found.`（warning）: 引数の無い呼び出しの名前違い、または一度も代入していない変数を読んでいる。変数を意図して読んでいるのなら問題ない（`＊初期化` で初期値を入れる書き方がある）ので、打ち間違いでないかだけ確かめる。存在しないジャンプ先（`＞名前 not found.`）は、辞書が意図して使うことが多いので、`check-dic` は表示しない（`shiori.ps1` では `[note]` で出る）。
- タイマや入力ボックスから呼ばれる文（そのときだけある変数を読む文）は、名前で直接実行すると意味のない警告が出る。その文の `＊` の行のすぐ上に、`check-dic: no-run` を含むコメント行（`＃check-dic: no-run（理由）`）を書くと、`-Run` で実行しない。実行しなかった数は、最後の行に `(N marked no-run)` と出る。同じ名前の文が複数あるときは、1 つに書けば、その名前はすべて実行しない。
- 名前のない文（ランダムトーク）は `-Run` では実行されない。`scripts/shiori.ps1 -Event OnTalk` で 1 つ実行される（選ばれるのはランダムなので、何度か実行する）。

`-Run` は、SAORI を使う文も本当に実行する（`＠SAORI` に登録した SAORI は動く）。画面や PC に影響する SAORI を使うときは、その文の中身を読んでから実行する。

## shiori.ps1 のエラー

`-Eval` や `-Event` の後に、里々のログから拾ったエラー（`[error]`）・警告（`[warning]`）・参考（`[note]`）が出る。終了コード 2 なら、表示された内容（`[in ＊名前]` が、そのとき実行していた文）から直す。使い方は `references/satori/commands.md`。

## 補足

- チェックは `ghost/master` の一時コピーで行う。里々が終了時に書く `satori_savedata.txt` / `satori_savebackup.txt` を、本物のフォルダに残さないため。
- `satori.dll` は、ビルドによっては `[ERROR]` の通知が遅れたり、まとめて出たりする。ログの通常の行からも拾っているので、表示は変わらない。
- tamacs.exe は `Set_loghandler` で里々のログを受け取る。`Set_loghandler` は里々 Mc201-10 から入ったので、それより古い `satori.dll` では、チェックが SKIPPED（終了コード 3）になる。`references/satori/update.md` の手順で更新する。
