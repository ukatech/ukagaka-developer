# YAYA 辞書の書き方の要点

YAYA のゴーストの辞書（`ghost/master/dic/` の `.dic`）を書くときの要点。細かい文法と関数は yaya-docs で確かめる（`SKILL.md` の「仕様を調べる」。1 ページにまとまった https://yaya-shiori.github.io/yaya-docs/startup/cheatsheet/ が入口になる）。ゴースト固有の決まり（どの辞書ファイルに何を書くか、キャラクター、口調）は `GHOST.md` にある。

## YAYA のバージョン（YAYA 6 が前提）

このスキルは、YAYA 6（600 系。`yaya.dll` が `Tc6xx`）のゴーストを前提に書いている。系列は `scripts/doctor.ps1` の `yaya.dll 6, 07, …` の先頭の数で分かる（5 なら 500 系）。

- **サポート対象は 600 系だけ。** YAYA 開発チームが更新しているのは Tc6xx だけで、500 系（Tc5xx）は、致命的な問題があるときに限りバックポートが検討される程度。
- **500 系のゴーストでは、作者に YAYA 6 への更新を強く推奨する**（頼まれるまで自分では更新しない。手順は `references/yaya/update.md`）。`yaya.dll` を置き換えるだけ（drop-in）で、500 系の辞書とセーブファイルがほぼそのまま動き、互換性についての報告も些細なものしかない。細かい変更点は yaya-docs の `other/changes-600.md`。
- 作者が 500 系のままにすると決めたら、そのゴーストでは 600 系の機能を使わない。ハッシュ、入れ子の配列、多次元代入、2 変数の `foreach`、JSON / XML / YAML / TOML / HTML / SQLite の関数は、500 系ではエラーになる。500 系と 600 系の両方で動かす辞書は、`#ifdef __AYA_SYSTEM_YAYA6__` で書き分ける（Tc574-2 以降の 500 系、Tc602-2 以降の 600 系）。
- 600 系の中でも、機能ごとに入った版が違う（正規表現のエンジンが変わった Tc606-6 など）。版が書いてある機能は、ゴーストの `yaya.dll` がその版以降か確かめてから使う。

## 辞書の書き方

- 関数は `関数名 { ... }` で定義する。`{ }` の中に文字列を並べると、呼ばれるたびにその中から 1 つが選ばれる。`関数名 : nonoverlap { ... }` とすると、一巡するまで同じものを選ばない。
- `--` を挟むと、前後のブロックの結果をつなげて 1 つの出力にする。
- 文字列:
  - `"..."` の中では `%(変数名)` や `%(関数名)` が展開される。`"` そのものは `""` と重ねて書く。
  - `'...'` の中は展開されない。
  - テンプレートから作ったゴーストでは、ランダムトーク本体の `RandomTalkEx` は `'...'` で書くが、呼び出し側の `RandomTalk` が展開するので `%(username)` などが使える（ゴーストによって違うので、既存の辞書に合わせる）。
  - バックスラッシュはエスケープ文字ではない。`'\0\s[0]'` はそのままさくらスクリプトとして出力される。
- 行末に `/` を書くと、次の行に続けて書ける。
- `_` で始まる変数はローカル変数。それ以外はグローバル変数で、`yaya_variable.cfg` に自動で保存され、次に起動したときに戻る。
- イベントの引数は `reference[0]`、`reference[1]`、…（`reference0` の形でも読める）。
- 制御構文は `if` / `elseif` / `else`、`case 値 { when 'a' { ... } others { ... } }`、`while`、`for`、`foreach`。条件に `( )` は要らない（付けてもよい。600 系の Tc603-6 からは `for` / `foreach` のヘッダ全体も `( )` で囲める）。
- コメントは `//` と `/* */`。
- チェイントーク: トークの最後に `\e:chain=ラベル` と書くと、その後のランダムトークが `ラベル {{CHAIN ... }}CHAIN` に並べたトークから順に選ばれる。`{ }` で囲んだ部分はその中からランダムに選ばれる。
- 新しいイベントに反応させるには、イベント名と同じ名前の関数を書く。どの辞書ファイルに書くかは `GHOST.md` の「イベントと辞書ファイルの対応」を見る。`yaya.txt` が読み込むフォルダに新しい `.dic` ファイルを置いた場合も自動で読み込まれる。同名の関数が複数あるとエラーになる。
- 辞書のエラーは `scripts/check-dic.ps1` で調べる。未使用・未定義の名前は `scripts/lint.ps1`。見方は `references/yaya/check.md`。

## ハッシュと入れ子（YAYA 6）

YAYA 6 には、キーで値を引くハッシュ（連想配列）と、配列やハッシュを要素にできる入れ子（多次元データ）がある。仕様は yaya-docs の `grammar/12-hash.md` と `grammar/13-nesting.md`。以下は Tc603-1 以降の動作（無いキーの読み出しが VOID になった版。それより前の 600 系は、無いキーが空文字列になり、配列の中の配列の書き換えで入れ子が崩れる）。値の型は、汎用配列、簡易配列（`,` 区切りの文字列）、ハッシュ（`GETTYPE` が 5）。

- **作る**: `IHASH("name", "さくら", "age", 16)`（キーと値を交互に並べる）、空は `IHASH()`、文字列からは `HASH_SPLIT("a=1,b=2", ",", "=")`。**ハッシュは最初に `IHASH` で作る。** 未定義の変数に `_x["a"] = 1` と書いても、ハッシュにならず配列 `(1)` になる。グローバル変数は `if GETTYPE(g) != 5 { g = IHASH() }` のように、型を見てから作る。
- **読み書き**: `h[キー] = 値`、`h[キー]`。キーが無いと VOID が返る（未定義の変数と同じ。`== ""` は真、`+ 1` は整数の 1）。このため `_c[名前] += 1` は、キーが無くても数えられる。キーの有無は `HASH_EXIST(キー, ハッシュ)`（**引数の順はキー、ハッシュ**）、要素数は `HASH_SIZE`、キーの配列は `HASH_KEYS`、値の配列は `HASH_VALUES`。
- **キーと並び**: `h[1]` と `h["1"]` と `h[1.0]` は同じキー。要素は**挿入した順ではなく、キーの順**（数値、文字列の順）に並ぶ。順序に意味を持たせたいときは、キーを連番にするか、配列を使う。
- **回す**: `foreach _h ; _k, _v { ... }` でキーと値を受け取る（配列でも `foreach _a ; _i, _v` で添字と値）。`foreach _h ; _v` は値だけ。
- **入れ子**: ハッシュの値にも配列の要素にも、配列やハッシュを入れられる。`_h["list"] = (1, 2, 3)`、`_h["sub"] = IHASH("x", 1)` のあとは、`_h["sub"]["x"]`、`_h["list"][1]` のように `[ ]` をつなげて読め、`_h["list"] ,= 4`、`_h["sub"]["x"] += 1` のように、`=` 以外の代入（多次元代入）もできる。
- **配列の中に配列を直接並べる書き方はない。** `((1, 2), (3, 4))` も `_a ,= (5, 6)` も、右辺の配列が展開されて平らな配列になる。行ごとに長さが違うデータ（ジャグ配列）は、次のどれかで作る。
  - ハッシュの値に配列を入れる: `_g[0] = (1, 2, 3)`、`_g[1] = (4)`、`_g[1] ,= 9`。キーを 0, 1, 2… の連番にすれば二次元配列のように使える（`_g[0][2]` で読む。行数は `HASH_SIZE(_g)`）。
  - 配列にハッシュ（レコード）を足す: `_list = IARRAY`、`_list ,= IHASH("name", "A", "n", 1)`。ハッシュは展開されず 1 つの要素になる。`_list[0]["n"] += 10` で書き換えられる。
  - `PARSEJSON('[[1,2,3],[4]]')` や `FREADJSON` で読み込む。得られた内側の配列も、`_v[0] ,= 9` のように書き換えられる。
- **途中の段は自動では作られない。** `_e = IHASH()` のあとで `_e["n"]["x"] = 5` と書くと、`_e["n"]` はハッシュでなく配列 `(5)` になる。先に `_e["n"] = IHASH()` で作る。
- **関数に渡す**: 引数で展開されるのはいちばん外側の配列だけで、内側の配列とハッシュは 1 つの引数のまま渡る。受け取る側で「引数が 1 つの配列」と「複数の引数」を区別できないので、入れ子のデータはハッシュに包むか、1 つずつ渡す。
- **コピー**: 代入や引数渡しは、内側までコピーする。`_sub = _h["sub"]` を書き換えても `_h` は変わらない。元を変えるときは、多次元代入で書くか、書き換えたものを代入し直す。
- **確かめる・保存する**: 文字列にすると構造が消える（`TOSTR` で `l=1,2,m=x=1` のようになる）。中身は `DUMPVAR` で見て、文字列で受け渡すなら `DUMPJSON` / `PARSEJSON`、ファイルなら `FWRITEJSON` / `FREADJSON`（YAML、TOML、XML もある）。グローバル変数のハッシュと入れ子は、そのまま `yaya_variable.cfg` に保存され、次の起動で戻る。

例（既存の `OnMouseDoubleClick` があれば、その中に組み込む。同名の関数を足すと重複エラーになる）:

```
OnMouseDoubleClick
{
    if GETTYPE(nadenade) != 5 {
        nadenade = IHASH()
    }
    nadenade[reference[4]] += 1       // 当たり判定の名前ごとに数える

    _n = nadenade[reference[4]]
    "\0\s[0]%(reference[4])を触られたの、これで%(_n)回目だよ。\e"
}
```

## 正規表現（RE_ 関数）

`RE_` で始まるシステム関数が、文字列を正規表現で検索・分割・置換する。仕様は yaya-docs の `grammar/14-regular-expressions.md`。

- **使い分け**: 一部が合うか `RE_SEARCH`、全体が合うか `RE_MATCH`、合う部分すべて `RE_GREP`、分割 `RE_SPLIT`、置換 `RE_REPLACEEX`（`$1`、`${name}` が使える）。**`RE_REPLACE` は置換文字列をそのまま使う**ので、`$1` は使えない。合った内容・位置・長さは `RE_GETSTR` `RE_GETPOS` `RE_GETLEN`、オプション（`i` `m` `s` `x`。既定はなし）は `RE_OPTION("i")` で設定する。
- **パターンは `'...'` で書く**（`"..."` だと `%(...)` が展開される）。`\` はそのまま正規表現に渡るので、`'\d+'` と書ける。
- **日本語**: `\d` `\w` `\s` `\b` は ASCII だけが対象で、全角の数字や日本語にはマッチしない。日本語は `\p{Hiragana}` `\p{Katakana}` `\p{Han}` で判定する（Tc606-6 以降。それより前の DEELX では、`\p{Hiragana}` はエラーにならずに、マッチしないだけ）。
- **戻り値を捨てると、出力候補に混ざる。** `_r = RE_SEARCH(...)` のように、変数で受ける。
- **エンジン**: Tc606-6 から uka_regexp（PCRE2 に近い構文。先読み・後読み、Unicode プロパティなどは uka_regexp の README が詳しい）。それより前は DEELX で、基本の書き方は同じだが、`\p{...}` や次の部品の呼び出しは使えない（`(?&名前)` はエラーにならずに、マッチしないだけ）。
- **部品の組み立て**（Tc606-6 以降）: パターンの中の `(?&名前)` は、ローカル変数 `_名前`、グローバル変数 `名前`、関数 `名前` の順に探して見つけた値（文字列か数値）を、パターンとして取り込む。`_y = '\d{4}'`、`_date = '(?&y)-\d{2}'` のように、長いパターンを組み立てられる。変数が無いと同名の関数が実行されるので、部品用の名前は他の関数や変数と重ならないものにする。

## トーク（さくらスクリプト）の書き方

間の取り方、改行の入れ方、話し手の交代などの決まりと例は、`GHOST.md` の「トークの書き方」にある。どのゴーストにも共通すること:

- 話し始める側のスコープ（`\0` / `\h`、`\1` / `\u`）と表情（`\s[番号]`）を最初に指定する。サーフェス番号は `GHOST.md` の表にあるものだけを使う。
- `\w1` はおよそ 50 ミリ秒の待ち、`\n` は改行、トークの最後は `\e`。

## YAYA でやりがちな失敗

共通の失敗（長すぎる台詞、存在しないサーフェス番号、口調の混在、`\\`、危険なタグなど）は `references/ai-guidelines.md`。YAYA では次にも気をつける。

- `'...'` の中に `%(変数)` を書いて、展開されない（`RandomTalkEx` のように、呼び出し側が展開する関数は例外）。
- 文字列を `"..."` で囲み忘れる（さくらスクリプトも文字列）。`"` を重ねずに文字列の中に書く。
- ブロック `{ }` の中で作ったローカル変数を、ブロックの外で読む。
- 同名の関数を別の辞書ファイルに足して、重複エラーにする（イベントの入口は 1 か所に書く）。
- システム辞書（`dic/system/`）を編集する。
- 500 系のゴーストで、作者に更新を強く推奨しないまま 600 系の構文（ハッシュ、入れ子の配列など）を使う。
- ハッシュを `IHASH` で作らずに `_x["a"] = 1` と書く（配列になる）。入れ子の途中の段を作らずに `_e["n"]["x"] = 5` と書く。
- 配列の中に配列を、`((1, 2), (3, 4))` や `,=` で作ろうとする（平らになる）。ハッシュの値に入れるか、`PARSEJSON` を使う。
- `HASH_EXIST` の引数の順を、ハッシュ、キーの順に書く（キー、ハッシュの順）。ハッシュの並びを、挿入した順だと思う。
- `RE_REPLACE` の置換文字列に `$1` を書く（`RE_REPLACEEX` を使う）。`RE_SEARCH(...)` の戻り値を捨てる。`\d` `\w` で日本語や全角の数字にマッチさせようとする。
